# 理记 · 轻享版

大纲 + 思维导图笔记。**没有服务端**：不要账号、不要登录、不要会员，打开就能写；
文档全部存在本机；想多设备同步，就在「同步与存储」里填一次自己的对象存储。

---

## 一、网络行为

本程序发出的网络请求只有一类：**去你配置的对象存储读写两个 JSON 文件**。
不发任何 `/api` 请求（自检里有一条断言钉住这件事）。

---

## 二、跑起来

```bat
双击 启动.bat          :: 起本地静态服务并打开浏览器（推荐）
node server.js         :: 只起服务，自己访问 http://127.0.0.1:5173
```

`server.js` 只是个**静态文件服务**（零依赖，约 100 行）：把 `index.html / app.js / oss.js / styles.css`
发出去而已，不存数据、没有接口。关掉它文档照样在 —— 文档在浏览器的 localStorage 里。

> 不建议直接双击 `index.html`（`file://`）：那条路上 Web Crypto 可能被禁、localStorage 行为也不一致，
> 对象存储签名会算不出来。

### 公网网页版（部署到静态托管，摆脱「同一局域网」限制）

网页版是**纯静态**的——`index.html / app.js / oss.js / styles.css / icon.svg` 五个文件，
把 `网页部署包\` 文件夹上传到任何静态网站托管，就能得到一个**不依赖电脑**的公网地址：
手机 / 平板 / 任何设备随时可用，不需要电脑开机、也不需要和电脑连同一网络。

作者自己长期用 **Cloudflare Pages**（免费、自动 HTTPS、默认域名可直接访问）：

1. Cloudflare 控制台 → Workers & Pages → Create → Pages → **Upload assets** →
   拖入 `网页部署包\` 文件夹，约 30 秒得到 `https://<项目名>.pages.dev`
2. 以后改了文件：进该项目 → **Create new deployment** → 再拖一次文件夹即可

> 为什么不用国内对象存储当网站：2024 年后新建的腾讯 COS / 阿里云 OSS 桶，
> 默认域名对网页文件**强制下载**；EdgeOne 默认域名只有 **3 小时**预览。
> 长期稳定请用 Cloudflare Pages，或给 EdgeOne / COS 绑自定义域名。

### 手机 / 平板访问（不用部署任何服务器）

```bat
双击 手机访问.bat
```

电脑和手机连**同一个 Wi-Fi**，双击后用手机浏览器打开「理记手机服务」窗口里打印的地址
即可 —— 网页版是纯前端的，电脑这台进程只发静态文件，
没有账号 / 数据库接口。要点：

- **首次启动**若弹出 Windows 防火墙提示，勾选「专用网络」并点「允许访问」，否则手机连不上；
- 手机浏览器里的文档与电脑**互不相通**（各存各的 localStorage）；
  想两边看同一份文档，在两台设备的「同步与存储」里填**同一个对象存储**；
- 手机走 `http://局域网IP` 不算安全上下文，Web Crypto 会被禁 ——
  `oss.js` 会自动落到内置的纯 JS 签名回退（离线自检对两条路都验过），功能不受影响；
- 服务只在电脑开机、双击了 bat 之后存在；关掉「理记手机服务」窗口就停，文档不受影响。

> 这个方案依赖电脑开机且同一局域网。想**彻底不依赖电脑**，用上一节的
> 「公网网页版」——把 `网页部署包\` 传到静态托管即可，任何网络都能访问。

## 三、接对象存储（可选，不配也能用）

「同步与存储」→「连接我的对象存储」，填一次，之后全自动。

支持三家：

| 服务商 | Bucket | Endpoint | 地域 |
|---|---|---|---|
| 阿里云 OSS | `my-bucket`（示例） | `https://oss-<地域>.aliyuncs.com`（示例，如杭州：`oss-cn-hangzhou`） | `cn-hangzhou`（示例） |
| 腾讯云 COS | `mybucket-1250000000`（示例，须带 APPID） | 留空 | `ap-guangzhou`（示例，必填） |
| S3 兼容（AWS / MinIO / R2） | `my-bucket`（示例） | `https://s3.example.com`（示例，MinIO/自建填你自己的服务地址） | `us-east-1`（示例） |

- **MinIO / 自建**：勾上「路径风格」。
- **阿里云新地域的桶**连不上（报 `SignatureVersionNotSupported`）→ 签名版本切 **V4**。
- 填完先点「测试连接」：它会写一个探针对象再删掉，验的是「能读能写能删」。

### 桶上必须配跨域（CORS）

浏览器直连对象存储必过这一关。在桶的「跨域设置 / CORS」里加一条：

```
来源 Origin     ：*        （或填 http://127.0.0.1:5173 —— 桌面端本地服务端口被占会顺延到 5174-5180，用 * 最省事）
允许 Methods    ：GET, PUT, HEAD, DELETE, OPTIONS（四个都要勾，缺 HEAD / DELETE 会读检与删除失败）
允许 Headers    ：*        （至少要有 authorization、content-type、x-amz-date、x-amz-content-sha256；阿里云是 x-oss-date）
返回 Vary: Origin：勾上
```

**腾讯云 COS 控制台对应填法**（基础配置 → 跨域访问 CORS 设置 → 添加规则）：

| 控制台字段 | 填什么 |
|---|---|
| 来源 Origin | `*`（一行一个；桌面端本地页来自 `http://127.0.0.1:5173`） |
| 操作 Methods | 勾 **GET、PUT、HEAD、DELETE**（POST 不用） |
| Allow-Headers | `*` |
| Expose-Headers | `ETag`（有就行，多填 Content-Length / x-cos-request-id 无妨） |
| 超时 Max-Age | `600`（0 也能用，只是每次都多一趟 OPTIONS 预检） |
| 返回 Vary: Origin | 勾上 |

> 不需要配 Expose-Headers 也不影响同步本身 —— 变化检测走 `meta.json`，不读 ETag / Last-Modified；
> 但测试连接与文件读回会读 ETag，建议照上表填。
> 保存后等 1-2 分钟生效；改完先用「测试连接」验证。

### 安全

AccessKey 以**明文存在本机浏览器存储**里（`liji_oss_config`，不混进文档库、不会随文档导出）。
建议单独建一个只授权这个桶的子账号来用。

## 四、同步规则

云端有四类对象（前缀默认 `liji/`，可改）：

- `liji/documents.json` —— 文档库本体（同步数据源：图片、公式、加粗颜色都在这里，md 表达不了）
- `liji/meta.json` —— `{ rev, updatedAt, docs, bytes, device }`，**只用来判断云端有没有变**
- `liji/docs/<文件夹>/<文档名>.md` —— **源文件镜像**：每次推送自动生成，与前端文件夹分类一致
  （未分类在 `docs/` 根）；改名 / 移动 / 删除都会跟着同步。它是给人看的纯文本，
  图片 / 公式等富文本仍在 documents.json 里
- `liji/logs/<设备名>.jsonl` —— **操作日志**：每台设备一份（谁也不写别人的文件，永不冲突）

多设备冲突不做时间戳二选一：meta 带 `rev` 版本号，推送前先比对——
云端有本机没见过的改动时**自动按文档三方合并**（只有一边改 → 那边赢；两边都改 → **保双份**，
云端那份插为「云端副本 时刻」，谁也不丢；本机删了云端又改 → 抢救成副本）。

行为：

| 时机 | 做什么 |
|---|---|
| 打开应用 | 读 `meta.json` 比对：云端空 → 上传本机；本机有未上传的改动 → 上传；云端更新 → 拉回本地 |
| 改动后 1.2 秒 | 自动上传（防抖；这 1.2 秒里刷新页面也不会丢改动 —— 脏标记是落盘的） |
| 每 60 秒 | 后台看一眼云端；页面在后台时不查 |
| 手动 | 页头「同步」按钮 / 「立即同步」 |

自动合并已是默认行为，但保留两个明确按钮兜底（合并结果不满意时把选择权交还给你）：

- 「用云端覆盖本机」—— 覆盖前会先把本机存一份
- 「用本机覆盖云端」
- 覆盖错了：「找回云端覆盖前的版本」一键回退

### 回收站（可选，需桶开启版本控制）

「同步与存储」→「回收站」：打开功能后点「检测版本控制」。检测通过后，删除文档时
桶里的 `.md` 源文件会带着删除标记保留在桶里，可随时列出来并**恢复成新文档**（副本，
不影响现有文档）。注意两点：

- 检测不到版本控制时，请先到对象存储控制台给桶开启「版本控制」——开启之后删除的文件才找得回；
- 恢复的内容来自纯文本镜像，不含图片 / 公式的原始数据（镜像里没有的，找不回来）。

## 五、自检

```bat
双击 自检.bat
```

或分开跑：

```bat
node tools/test-oss.js        :: 签名算法（离线：RFC 标准向量 + Node crypto 交叉比对 + 腾讯官方文档算例基线，55 项）
node tools/test-oss-e2e.js    :: 对象存储端到端（本地起模拟 S3，真实 SigV4 / COS 独立验签，含版本控制 / 回收站链路，39 项）
node tools/test-lite.js       :: 真浏览器端到端（Edge/Chrome 无头，含 .md 镜像 / 操作日志 / 回收站，78 项）
```

`test-lite.js` 验的是需求本身：没有登录页、不发 `/api`、文档刷新仍在、
配置能存、改动自动上传、云端改了打开时自动同步、覆盖前有备份、编辑器与导图没被改坏。

最后 9 项走的是**真指针 + 真键盘**（点侧栏「＋ 新建文档」→ 模板浮层 → 选模板 → 敲字 → 点「导图」→ 重开还在），
不调任何内部 API —— 「按钮还在不在、点了有没有反应、字进不进得去」只有这条路验得出来。
这几条做过对照实验：把 `.side-new` 类名改掉一次，9 条必须全红（确实全红）。

另有 9 条盯「矮窗口下内容被吞」这类问题（2026-10-06 修的两处 bug）：

- 「同步与存储」页滚不动 —— `.main` 是 `overflow:hidden`，这一屏原先没有滚动容器
  （实测 1192px 内容塞进 620px 视口，「本机存储」卡永远看不见）。
- 贴底浮层（模板 / 新建文件夹 / 移动到…）在矮窗口下超高被裁 —— 浮层是向上生长的，
  没有高度上限时会一路长到 589px，多出来的 229px 落在视口下面且滚不到。
  修法是给它们加 `.sheet.tall`（`max-height:88% + overflow-y:auto`），这个样式以前写了没人用。

★ 这类断言都**先把视口压矮**（620 / 360px）再测：视口够高时内容装得下，毛病根本不会暴露。
★ 判据的参照物必须是**视口**，不能是容器自己 —— 容器没限高时会长到跟内容一样高，
拿它当参照会得到「都看得见」的假结论（这条踩过一次，对照实验里判据没红才发现）。

## 六、打桌面端 exe（可选）

```bat
双击 打包.bat        :: 第一次会先装 electron / electron-builder（约 1-3 分钟）
```

产物 `dist/理记-轻享版-<版本>.exe`，双击即用，不需要 Node。

当前已打好：`dist/理记-轻享版-1.2.0.exe`（67.9 MB），打包时的冒烟自检

> 打包依赖（`electron/node_modules`）没有入库，`打包.bat` 第一次会先 `npm install`
> （也可直接 `node tools/build-exe.js` 重打）。

## 七、数据在哪 / 怎么清

- 文档：浏览器 localStorage，键名 `liji_store:*`
- 对象存储配置：localStorage 的 `liji_oss_config`
- 桌面端 exe：便携版落在 **exe 同级的 `理记数据\`**（换电脑把整个文件夹拷走就行）；
  只有 NSIS 安装版才用 `%APPDATA%\理记\data`。也可以用 `LIJI_DATA_DIR` 环境变量指定。

要清空：浏览器 F12 → Application → Local Storage → 删掉上面两组键；
或双击「重置数据.bat」看指引。

## 八、文件说明

```
index.html / app.js / styles.css   客户端
oss.js                             对象存储客户端：AWS SigV4 / 阿里云 OSS V1+V4 / 腾讯云 COS，零依赖
server.js                          本地静态服务（无数据库、无接口；HOST=0.0.0.0 时供手机访问）
启动.bat / 手机访问.bat             本机用 / 局域网给手机用（自检 / 诊断 / 打包 / 重置数据 同目录）
electron/                          桌面端外壳（main.js 本地模式）
tools/                             自检与打包脚本（make-bat.js 生成全部 .bat，勿直接编辑 .bat）
```

> `.bat` 脚本（启动 / 打包 / 自检 / 诊断 / 重置数据 / 手机访问）由 `tools/make-bat.js` 生成
> （GBK + CRLF），不直接入库，克隆后跑 `node tools/make-bat.js` 生成；
> `electron/build/icon.png` 可由 `tools/icon-render` 重新渲染，仓库里同时存了一份 base64
> 副本 `electron/build/icon.png.b64`（`node -e "require('fs').writeFileSync('electron/build/icon.png', Buffer.from(require('fs').readFileSync('electron/build/icon.png.b64','utf8'),'base64'))"`）。

> **为什么仓库里没有 `网页部署包\` 文件夹**：它只是根目录
> `index.html / app.js / styles.css / oss.js / icon.svg` 五个文件的拷贝，仓库里已有原件，
> 不再存重复（存两份容易改一处漏一处）。要部署到静态托管（见「公网网页版」一节），
> 把这五个文件复制到一个文件夹（或直接拖根目录文件）上传即可。
